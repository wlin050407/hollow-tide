# 第一阶段计划：可行性、主要风险、第一周安排

## 1. 技术可行性评估

| 目标 | 判断 | 依据 |
|---|---|---|
| 2 周内做出 Tide Altar 垂直切片（占位美术） | **高** | 需要的机制在原版都有先例：龙舟赛起点 `boatrace_start` 和游乐场小游戏 `carnivalgame_*` 都是"制作 → 激活 → 限时事件 → 奖励"的建筑。用到的 API 已在本机 build 756039 的脚本里逐一核实（见 API_NOTES.md） |
| 原创静态图标、简单建筑贴图 | **中高** | 规格明确（物品栏 64×64、DXT5）；转换工具成熟；难点是风格一致性，只能靠人审 |
| AI 辅助的原创动画敌人 / Boss | **中低** | 见风险 1。这是整个项目最不确定的部分，第 2 周要尽早验证 |
| 16 周发布一个"大型"内容 Mod | **取决于投入时间** | 目前不知道三个人每周能投入多少小时。第一周结束时会得到第一个真实数据点，再调整范围 |
| 直接从 DST Mod 获得收入 | **低** | Workshop 订阅没有分成；Klei 的规则限制商业化（见第 5 节） |

结论：第一阶段技术上没有障碍，可以按计划推进；真正的不确定性在动画美术管线和团队产能，而不是 Lua 代码。

## 2. 最容易失败的三个环节

### 风险 1：AI 图像 → DST 动画资产（最可能失败）
- **为什么**：DST 的动画是 Spriter 切片动画（build 里的部件 + bank 里的动画数据）。生物需要多个朝向、每个部件有枢轴点、帧与帧之间严格一致。AI 擅长出一张好看的图，但不擅长"同一个角色的 20 个部件、3 个朝向、风格完全一致"。逐帧 AI 动画还会闪烁。
- **征兆**：花了两周美术时间，游戏里还是没有一个能动的原创物体；或者能动但和原版放在一起明显"不是一个游戏"。
- **对策**：
  - 第一阶段只做静态图标 + 少量状态的建筑动画（部件变换，不逐帧）
  - 生物设计从一开始就按"刚体部件能拼出来"的思路画：少部件、大色块、粗轮廓
  - 第 2 周设硬性检查点：一个原创物体、≥3 个动画状态、在游戏里正常播放。达不到就缩小美术范围，而不是继续堆时间

### 风险 2：服务器/客户端同步与存档（最隐蔽）
- **为什么**：一个人开不带洞穴的世界时，你的游戏同时是服务器和客户端，大量联机 bug 不会出现；它们会在发布后、别人用专用服务器时集中爆发（客户端访问不存在的组件、netvar 声明顺序错、事件中途存档读档后状态错乱、刷奖励）。
- **对策**：
  - 默认测试环境 = **带洞穴的世界**（你的游戏是纯客户端）。你平时就是这样开档的，见 TESTING.md
  - 日志统一带 `[server]` / `[client]` 标签，三份日志一起看
  - 每个功能都有"存档 → `c_reset()` → 验证"的用例；第 7 天专门做异常测试
  - 架构规则写进 ARCHITECTURE.md 和 AGENTS.md，AI 写代码时也必须遵守

### 风险 3：范围失控与 AI 编造 API（最致命）
- **为什么**："大型 Mod + 品牌 + AI 管线 + 社区"对三个人的业余时间来说非常大。AI 能加快写代码，但审查、进游戏测试、调手感、美术判断都是人的时间，而且这部分不会因为 AI 而变少。DST 没有官方文档，AI 会自信地写出不存在的函数，每次排查都在消耗这部分时间。
- **对策**：
  - 每周都以"能进游戏玩的东西"为交付，不交付文档或半成品管线
  - `tools/check_mod.py` 用游戏自带的脚本核对 API，AI 编造的函数在进游戏前就会被拦下（已用故意写错的代码验证过）
  - 记录每项任务的实际耗时，第一周末按真实产能重排 16 周计划
  - 一次只推进一个玩法功能

## 5. 品牌与商业化：需要修正的一个假设

Klei 官方的 [Player Creation Guidelines](https://support.klei.com/hc/en-us/articles/360029880791)（页面标注更新于 2022-10-17）写的是：
- 玩家创作的**商业使用一般不允许**，只有列出的少数例外（如个人手工制作的小批量实物）；其他情况要联系 Klei
- **页面没有提到捐赠 / Patreon**
- 视频（YouTube、Twitch 等）**可以放广告**

[Klei 的 Mod 规则](https://support.klei.com/hc/en-us/articles/360029557172-I-am-Interested-in-Modding-Don-t-Starve) 还禁止：未经许可使用他人素材、使用其他游戏或媒体的素材、绕过皮肤/DLC 等付费内容。

因此：
1. 在拿到 Klei 的书面答复之前，**不要**开设与 Mod 挂钩的捐赠渠道。建议第 4 阶段前通过 Klei 客服或论坛正式询问。
2. B 站 / YouTube 的开发日志和宣传视频收入是规则明确允许的，可以作为早期的合规收入方向。
3. 原创美术和世界观从第一天就由你们自己掌握版权，将来做独立游戏时可以带走；Klei 的素材和动画数据不能带走。
